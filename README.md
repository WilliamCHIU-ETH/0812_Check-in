## Context

我原先以「先做籌碼面，走通後再擴充到其他投資面向」探索籌碼 K 線 Lite。

## 這次主管回饋的核心

主管指出，目前的思考容易被「籌碼 K 線 Lite」這個任務名稱框住，從既有產品直接進入簡化 Solution。

如果目標是服務目前不在既有 user pool 的新手，應先回到根本，理解這群人如何投資、現在如何解決問題，再決定要提供什麼產品。主管將這種不預設既有產品為答案的思考稱為「歸零思考」。

> 先確認問題，再決定是改善既有產品，還是重新定義產品。

## 先用問題樹回到根本

```mermaid

    A["新手真的需要這類工具嗎？"]
    B["這是不是他會主動解決的問題？"]

    D["現有解法造成什麼具體痛點？"]
    E["為什麼不用既有籌碼產品？"]
    F["技術性問題<br/>想用籌碼做決策<br/>但工具太複雜"]
    G["需求性問題<br/>本來就不靠籌碼做決策"]
    H["改善既有籌碼 K 線<br/>資訊分層／首用體驗"]
    I["歸零設計新產品<br/>不預設籌碼是入口"]
    J["共同出口關卡：是否『十倍好』？<br/>新方案價值 &gt; 現有解法價值 + 使用者轉移成本"]

    A --> B --> C --> D --> E
    E --> F

    F --> H --> J
    G --> I --> J
```

這不是一組可以任意挑選的問題。前一層成立後，才進入下一層；如果使用者沒有需求，或這不是他會主動解決的問題，就不應直接進入介面設計。

### 技術性問題

如果使用者本來就想用籌碼做投資判斷，只是既有產品的資訊量、操作方式或理解門檻太高，方向應是改善既有產品。

可能的做法包括資訊分層、漸進式揭露，以及調整第一次使用時的 UI 與 Flow。此時應解決既有產品的問題，而不是另外建立一個只對既有產品做減法的新產品。

### 需求性問題

如果使用者原本就不靠籌碼做投資決策，將籌碼 K 線簡化，也不一定會讓他開始使用。

此時應回到這群人的投資任務、決策方法與現有解法，重新思考要提供什麼產品，而不是預設籌碼是入口。

新手即使買個股，也不代表他以籌碼作為決策方法。他可能同時持有 ETF、基金與個股，也可能依題材、趨勢或其他方法判斷；若投資方法不同，產品命題也會跟著改變。

## 「十倍好」的出口關卡

無論最後改善既有產品或歸零設計新產品，都要回答：新方案是否比使用者的現有解法好到足以克服轉移成本？

> 新方案價值 > 現有解法價值 + 使用者轉移成本

主管以「十倍好」說明這個差距必須可以具體衡量，例如用時間或金錢比較；若原本完成任務需要一小時，十倍快代表約六分鐘完成。

## 主管提出的兩個例子

### 襯衫與拉鍊

如果一個人不穿襯衫，是因為不喜歡襯衫，把鈕扣換成拉鍊也不會產生需求。

這個例子用來區分：問題究竟是產品不好用，還是使用者根本不需要這類產品。

### 做減法與歸零設計新產品

主管以 Robinhood 為例說明，面向新使用者的產品不一定只是從複雜產品中刪除功能，也可能需要重新設計 UI、互動方式、獲客機制與整體產品組合。

因此，「簡化既有產品」與「為不同使用者重新定義產品」是兩條不同路線。

## 我的反思

我目前還沒有分清楚：新手不用籌碼產品，主要是使用摩擦，還是投資需求與方法不同。

## 下一步

先釐清目標使用者的需求、決策方式與現有解法，再決定應改善既有產品，或重新定義產品方向。

## 證據邊界

這次回饋提出了需要釐清的問題，但沒有證明籌碼面不值得做，也沒有拍板 Lite 應繼續、併入既有產品或停止。

錄音不包含真人使用者研究，因此不能用來證明需求、採用或產品價值成立。
